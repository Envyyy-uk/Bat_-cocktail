# S&W Bar — коктейльна карта

Статичний сайт-меню бару: 26 коктейлів (класика, фірмові рецепти та безалкогольна лінійка) з фото, покроковим методом приготування, нумерованим списком інгредієнтів та історією кожного напою.

## Структура сайту

- **`index.html`** — головна сторінка: фото бармена, короткий опис бару, кнопки-переходи по категоріях.
- **`cocktails.html`** — повна коктейльна карта. Список з пошуком і фільтром за категорією; клік по картці відкриває окрему "сторінку" коктейлю (маршрутизація через `#/c/<slug>`, тому на кожен коктейль є пряме посилання, наприклад `cocktails.html#/c/mai-tai`).
- **`my-bar.html`** — вкладка "Мій бар": підбір коктейлів за інгредієнтами, які є вдома, та форма додавання власного коктейлю (фото, інгредієнти, метод, історія).
- **`js/data.js`** — усі дані коктейлів в одному місці.
- **`css/style.css`** — стилі всього сайту.

## Фото

Реальних фото коктейлів та бармена поки немає, тому сайт малює акуратні SVG-плейсхолдери
(силует бокала в кольорі напою / силует бармена). Щоб підключити справжні фото:

- Фото бармена → додай файл `images/bartender.jpg`.
- Фото коктейлю → додай файл `images/cocktails/<slug>.jpg` (назва файлу = slug коктейлю з `js/data.js`, наприклад `images/cocktails/mai-tai.jpg`).

Як тільки файл з'явиться за потрібним шляхом, сайт автоматично покаже фото замість плейсхолдера — правити код не потрібно.

## Власні коктейлі

Форма на вкладці «Мій бар» зберігає додані коктейлі (разом із фото) у `localStorage`
браузера відвідувача. Це статичний сайт без бекенда й бази даних, тому власні рецепти
видно лише на тому пристрої й у тому браузері, де їх додали — вони не потрапляють у репозиторій і не видно іншим відвідувачам сайту.

## Публікація на GitHub Pages

У репозиторії є workflow `.github/workflows/pages.yml`, який автоматично деплоїть сайт
при push у гілку `main`. Щоб посилання запрацювало, потрібно один раз (вручну, в налаштуваннях репозиторію — я не маю до них доступу):

1. Відкрити **Settings → Pages** у репозиторії на GitHub.
2. У полі **Source** обрати **GitHub Actions**.
3. Після цього при кожному push у `main` workflow сам збере і опублікує сайт, а посилання буде виду `https://<username>.github.io/<repo>/`.
